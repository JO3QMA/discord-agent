# 分割投稿は構造を優先する

Discord 本文上限を超える返信は、文字数での途中切断を既定にしない。段落 → 行 → 強制切断の順で分け、上限に収まるあいだ完成単位を貪欲に同一メッセージへ載せる。表とコードフェンスは可能な限り塊のまま扱い、表を割るときはヘッダ（と区切り）を繰り返し、フェンスを割るときは各通で開閉して言語タグを引き継ぐ。入口からの長い本文は同一規則とし、通し番号は付けない。装飾・接頭辞込みの送信直前文字列が Discord 上限に収まること。分割後の通数には上限を置き、超えた分は truncate する（レート制限・チャンネルスパム回避）。素の `slice` より実装は重いが、表や文章の途中切れで読めなくなるコストの方が大きい。
